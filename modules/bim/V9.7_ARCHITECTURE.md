## 2. Feature Requirements

### 2.1 Model Tree (Hierarchical Navigator)

#### Structure Options
```
Option A: IFC Spatial Hierarchy
└── Project
    └── Site
        └── Building
            └── Storey
                └── Space
                    └── Elements (by type)

Option B: Type-Based Hierarchy
└── Project
    ├── Architecture
    │   ├── Walls
    │   ├── Doors
    │   └── Windows
    ├── Structure
    │   ├── Columns
    │   ├── Beams
    │   └── Slabs
    └── MEP
        ├── HVAC
        ├── Plumbing
        └── Electrical

Option C: Hybrid (Recommended)
└── Project
    ├── By Location (spatial hierarchy)
    ├── By Type (type-based)
    └── By Discipline (MEP, Architecture, Structure)
```

**Decision**: Implement **Option C (Hybrid)** with user-selectable view modes.

#### Tree Node Features
- **Expand/Collapse**: Hierarchical navigation
- **Checkboxes**: Visibility toggle (with tri-state for parents)
- **Icons**: Visual indicators for element types
- **Count Badges**: Number of child elements
- **Selection Sync**: Tree ↔ Viewer selection synchronization
- **Context Menu**: Right-click actions (isolate, hide, properties)
- **Search**: Incremental search with highlighting
- **Virtual Scrolling**: Performance for large models (10,000+ elements)

#### Tree View Modes
1. **Spatial**: IFC building hierarchy (IfcProject → IfcSite → IfcBuilding → IfcStorey)
2. **Type**: Grouped by IFC type (IfcWall, IfcBeam, IfcColumn, etc.)
3. **Discipline**: Architecture, Structure, MEP, Civil
4. **Custom**: User-defined grouping by properties

### 2.2 Element Visibility Controls

#### Visibility Modes
- **Show All**: Display all elements
- **Hide All**: Hide all elements (except active selection)
- **Isolate**: Show only selected elements
- **Transparent**: Make elements semi-transparent instead of hidden
- **Ghosted**: Show hidden elements as wireframe/ghost

#### Visibility Filters
- **By Type**: Show/hide by IFC type (walls, doors, windows, etc.)
- **By Discipline**: Architecture, Structure, MEP
- **By Level/Storey**: Show specific building levels
- **By Status**: Filter by workflow status (approved, in review, etc.)
- **By Properties**: Custom property-based filters
- **By Clash Status**: Show elements with clashes

### 2.5 Selection Management

#### Selection Tools
- **Select All Visible**: Select all currently visible elements

- **Clear Selection**: Deselect all

#### Viewer Integration (xeokit-sdk)

```javascript
// viewer/ViewerManager.js
class ViewerManager {
  constructor(canvas, modelId) {
    this.viewer = new Viewer({ canvasId: canvas });
    this.modelId = modelId;
    this.model = null;
    this.selection = [];
  }

  // Load model
  async loadModel(url) {
    const xktLoader = new XKTLoaderPlugin(this.viewer);
    this.model = xktLoader.load({ id: this.modelId, src: url });
  }

  // Selection management
  selectElements(guids) {
    this.viewer.scene.setObjectsSelected(guids, true);
    this.selection = guids;
    this.emit('selection-changed', guids);
  }

  // Visibility management
  setVisibility(guids, visible) {
    this.viewer.scene.setObjectsVisible(guids, visible);
  }

  isolateElements(guids) {
    this.viewer.scene.setObjectsVisible(
      this.viewer.scene.objectIds,
      false
    );
    this.viewer.scene.setObjectsVisible(guids, true);
  }

  // Color override
  setColors(colorMap) {
    Object.entries(colorMap).forEach(([guid, color]) => {
      this.viewer.scene.setObjectsColorized([guid], color);
    });
  }

  // Camera control
  flyToElements(guids) {
    this.viewer.cameraFlight.flyTo({
      aabb: this.viewer.scene.getAABB(guids),
      duration: 0.5
    });
  }
}
```

## 5. Performance Considerations

### Virtual Scrolling
- Render only visible tree nodes (20-50 at a time)
- Use `vue-virtual-scroller` or custom implementation
- Target: Smooth scrolling with 10,000+ nodes

### Lazy Loading
- Load tree nodes on-demand when expanded
- Cache loaded nodes in Vuex store
- Prefetch next level on hover

### Debouncing
- Search input: 300ms debounce
- Filter changes: 500ms debounce
- Property updates: 1000ms debounce

### Caching Strategy
```javascript
// Browser cache
localStorage.setItem('bim_tree_expanded_nodes', JSON.stringify(expandedNodeIds));
localStorage.setItem('bim_panel_sizes', JSON.stringify(panelSizes));

// Server cache
Redis.cache(`bim:model:${modelId}:tree`, treeData, ttl: 1.hour);
Redis.cache(`bim:element:${guid}:properties`, properties, ttl: 15.minutes);
```

### Viewer Performance
- Use xeokit's geometry batching
- Limit selection highlighting to 1000 elements
- Throttle selection events to 60fps
- Use WebWorkers for tree building

## 10. User Stories

### US-1: Navigate Model Hierarchy
**As a** BIM Coordinator
**I want to** browse the model hierarchy in a tree view
**So that** I can quickly navigate to specific elements or groups

**Acceptance Criteria**:
- Tree shows spatial hierarchy by default
- Can switch between spatial, type, and discipline views
- Nodes expand/collapse with smooth animation
- Search finds elements incrementally
- Double-click zooms to element in 3D view

### US-2: Inspect Element Properties
**As a** Project Manager
**I want to** view detailed properties of selected elements
**So that** I can verify specifications and materials

**Acceptance Criteria**:
- Properties panel shows all IFC properties
- Properties grouped by category with collapsible sections
- Can copy property values to clipboard
- Multi-select shows common properties
- Property history shows who changed what when

### US-3: Control Element Visibility
**As a** MEP Engineer
**I want to** hide architectural elements to focus on MEP systems
**So that** I can analyze MEP layout without visual clutter

**Acceptance Criteria**:
- Can filter by discipline, type, or level
- Tree checkboxes control visibility
- Isolation mode shows only selected elements
- Exit isolation restores previous state
- Visibility state saved with view

### US-4: Find Specific Elements
**As a** Architect
**I want to** search for elements by name or properties
**So that** I can quickly locate specific components

**Acceptance Criteria**:
- Search finds elements as I type
- Can search by name, type, or property
- Results highlight in tree and viewer
- Advanced search supports multiple criteria
- Can save frequently used searches

### US-5: Visualize by Status
**As a** QA Manager
**I want to** color-code elements by approval status
**So that** I can quickly see which elements need review

**Acceptance Criteria**:
- Can apply color schemes (status, discipline, type)
- Colors update in real-time
- Legend shows color mapping
- Can reset to original colors
- Color scheme saved with view

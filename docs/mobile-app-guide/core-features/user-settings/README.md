# Account and settings

The **Account and settings** module allows you to manage your account, personalize and set up the OpenProject mobile app. It also provides access to help, release information, and support channels.

## What you can do

### Basic account information

Review, and where supported, update your account information, such as:

- **Avatar** (not editable)
- **Username** (not editable)
- **First name**
- **Last name**
- **Email address**

> [!NOTE]
> Some fields may be read-only in the mobile app, depending on how your OpenProject instance manages user accounts.

### Personalization

Adjust how the app behaves and how it looks:

- **Launch page**: choose what the app opens by default.
- **Enabled modules**: control which modules appear in the app navigation.
- **Language**: set the app language.
- **Theme**: switch between **light mode,** **dark mode**, or switch depending on the **OS theme**.

### Notification settings

Control **what you receive notifications for**.

This typically includes:

- **Participation notifications** (e.g., when you are mentioned, assigned, watching, etc.)
- Non-participation notifications (e.g., new work packages, all date changes, all status updates, etc.)
- **Date alerts** (e.g., reminders or date-related notifications, depending on configuration)

Use these settings to reduce noise and focus on what matters to you.

> [!NOTE]
> These settings are global. If you change them in the app this will also affect what notifications you receive in the core OpenProject browser app.

### Work package settings

Configure how work packages behave in the app.

This includes:

- **Activity tab “mark as read” behavior:** Choose how notifications/activities are marked as read when using the **Activity** tab (for example, automatically when opening it, only when commenting, or only when replying with a quote).
- **Creation settings:** Adjust defaults used when creating new work packages.
- **Default page for work package lists:** Choose which of the default queries opens when you enter work package lists.

### Crash reports (opt-in)

You can choose whether to share **crash reports** with OpenProject.

- Enabling crash reports helps improve the app by providing technical information when the app crashes.
- Disabling it prevents the app from sending crash diagnostics.

### Give feedback

Use **Give feedback** to contact the team and improve the app.

The feedback flow typically lets you:

- report a **bug**
- share general **feedback**
- request a **feature**

In all of these cases, you can also add attachments and provide a **follow-up email address** so the team can contact you if more information is needed.

### What’s new

Open **What’s new** to review highlights from the latest mobile app releases. This is useful to discover newly added features and UI changes.

### Mobile app documentation

The mobile app documentation opens documentation guides in your browser, so you can look up how modules work and what features are available.

### Switch instance

If you use multiple OpenProject instances, **Switch instance** lets you switch between instance URLs **without signing out** each time.

This is helpful when you work across multiple organizations or environments (for example, staging and production).

### Sign out

Ends your current session and signs you out of the OpenProject mobile app.

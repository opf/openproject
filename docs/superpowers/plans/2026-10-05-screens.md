# Screens Implementation Plan

> **Dành cho agent thực thi:** làm tuần tự từng task; mỗi step dùng checkbox. Viết test trước, chạy thấy fail đúng thông báo dự kiến, rồi mới viết code. Mỗi task có **Definition of Done (DoD)** và **Out of scope**; chỉ đóng task khi đủ DoD.

**Goal:** Module `modules/screens` cho phép admin định nghĩa Screen (create/edit/view/transition) gồm Section và Item (field + vị trí), gom thành Screen Scheme (Type → screen theo ngữ cảnh), gán cho Project; Resolver trả layout hiệu lực (hợp nhất trạng thái Field Rules) qua API v3 và UI xem trước/quản trị.

**Architecture:** Rails engine `modules/screens` theo mẫu `modules/field_rules`. 6 bảng mới. `::Screens::Resolver` là nguồn sự thật, fail-open, cache theo request. **Không** prepend vào core, **không** ghi `FormConfiguration`, **không** enforce. Phụ thuộc mềm `FieldRules::Resolver`.

**Tech Stack:** Rails 8.1, RSpec, Primer ViewComponent + Turbo + Stimulus (TypeScript), Grape API v3.

**Spec (nguồn sự thật):** [../specs/2026-10-05-screens-design.md](../specs/2026-10-05-screens-design.md) · **Idea:** [../../ideas/idea-03.md](../../ideas/idea-03.md) · **Checklist:** [2026-10-05-screens-checklist.md](2026-10-05-screens-checklist.md). Plan và spec mâu thuẫn ⇒ spec thắng; ghi chênh lệch vào checklist.

## Quy tắc xác minh (bắt buộc)

- Phiên hiện tại chỉ có Ruby 3.3.6 (repo cần 4.0.7), không Postgres/Docker/node_modules ⇒ không chạy được RSpec/rubocop/eslint. Mọi step "chạy test" thực hiện trên máy dev (`bin/compose-dev rspec …`).
- Mỗi task kết thúc bằng khối **Verification** trong checklist: lệnh, exit status, số pass/fail (dán nguyên văn). Chưa chạy ⇒ ghi `UNVERIFIED (not run)`, commit message của task mang `[unverified]`; **không** viết "tests pass" dựa trên việc đọc code.
- Mỗi lát (slice) đi trên nhánh/PR riêng từ nền xanh; PR là **draft** cho đến khi người chạy toàn bộ suite. Lát lỗi ⇒ `git revert` các commit của lát đó; migration đảo ngược được (`db:rollback STEP=1`); gỡ module = xoá một dòng ở `Gemfile.modules`.
- Không dùng `--no-verify`. Cài hook: `bundle exec lefthook install` (Task 0).

## Global Constraints

- Không sửa Ruby core, không thêm cột/bảng vào bảng core. Ngoại lệ có chủ đích: controller Stimulus mới + một import và một đăng ký ở `frontend/src/stimulus/setup.ts` (Task 9).
- Không có "jira" trong tên bảng/class/route/permission/menu/i18n/API/frontend.
- Tên DB: `type_id`, `scheme_id` (khớp F02); ánh xạ idea ở spec §7.1.
- Hằng giới hạn đặt trên model: `Screen::MAX_SECTIONS = 20`, `Screen::MAX_ITEMS = 100`, `ScreenScheme::MAX_ROWS = 200`. Trong engine/model/lib luôn viết `::Screens::…` (tránh `OpenProject::Screens`); namespace `Screens` chỉ có service, không có hằng.
- Không `DELETE` cho Screen/Scheme (`prevent_destroy`); deactivate qua `PATCH {active}` (API) / member `deactivate` (admin UI). `screen_type` bất biến (`attr_readonly`).
- Mọi thay đổi layout/scheme đi qua service có `with_lock`; cấm gán trực tiếp `section_id`/`position` từ params.
- Resolver fail-open theo mẫu F02 (log + `Rails.error.report` + trả `native/error`). Cờ module-local `::Screens::Resolver.raise_on_error` (mặc định `false`) để test kiểm chứng re-raise; **không** đổi `spec_helper`/`spec/support` của repo.
- Permission: manage = admin; `assign_screen_scheme` trong `project_module nil`; GET định nghĩa cho user đã đăng nhập; resolver endpoint 404 nếu project không visible hoặc type không bật; `diagnostics` chỉ cho admin/`assign_screen_scheme`.
- i18n: mỗi mã lỗi, giá trị enum (`create/edit/view/transition`, `full/half`), badge, `reason`, chuỗi `aria-live` đều có khoá trong `modules/screens/config/locales/en.yml` (và `js.screens.*` cho TS, có nội suy; không literal trong TS). Có spec `I18n.t(key, raise: true)` cho mọi khoá nêu trong spec.
- Mặc định **không comment** (CLAUDE.md); chỉ header copyright và ghi chú ràng buộc không hiển nhiên kèm liên kết. Không YARD.
- Header copyright cho mọi `.rb`, `.rake`, `.erb` (copy `<%#-- copyright … ++#%>` từ `modules/field_rules/app/views/admin/**/*.html.erb`), `.ts` (`rake copyright:update_typescript`). Task 12 chạy `rake copyright:*` kiểm toàn module.
- Commit: dòng đầu < 72 ký tự, dòng trống, thân mô tả, tham chiếu work package (hỏi người dùng nếu chưa có), trailer attribution của phiên.
- UI theo mẫu `modules/field_rules/app/views/admin/**` (Primer: `PageHeader`, `Flash`, `Button`, bảng có `caption`); không tạo component mới nếu không bắt buộc.
- Quality gates mỗi task: `bundle exec rubocop <files>`; `erb_lint <files>`; task frontend: `cd frontend && npx eslint src/stimulus && npm run typecheck`.
- Helper đếm truy vấn dùng chung (định nghĩa ở Task 3, `modules/screens/spec/support/query_counter.rb`, `require` từ các spec cần): đếm sự kiện `sql.active_record` trong `ActiveSupport::Notifications.subscribed`, loại `SCHEMA`, `TRANSACTION` và truy vấn cached. Ngưỡng cố định: `Resolver.for` ≤ 4; `Resolver.matrix` ≤ 4; so sánh bằng nhau giữa kích thước nhỏ và lớn cho mọi danh sách/editor/`for_many`.
